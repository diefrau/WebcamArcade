# 2026-11-17 최적화 적용 결과

## 적용한 변경

1. 벽 통과! 마스크용 ImageData와 RGB 채널을 같은 해상도에서 재사용한다. 매 프레임에는 알파만 갱신한다. 허리 페이드의 CanvasGradient도 재사용한다. 모델·신뢰도·FPS 제한·자세/명중 판정 규칙은 바꾸지 않았다.
2. 6개 게임의 플레이/결과 화면과 랭킹/도전과제 화면을 dynamic import로 분리했다. 홈 기록 표시는 검증 로직을 그대로 옮긴 경량 records 모듈을 읽는다. 쏴!의 기존 Context 의존성은 props로 전달하며 기록 저장 경로를 유지한다.
3. 링크에 마우스를 올리거나 키보드 포커스/터치가 들어오면 해당 목적지의 모듈만 받는다. Suspense 경계를 경로별 key 바깥에 두어 지연된 화면 전환 중에는 이전 화면을 유지한다. 로딩 스크린은 추가하지 않았다.
4. 카드·랜딩·결과용 캐릭터 7종에 320/640/960px 무손실 WebP와 srcSet/sizes를 추가했다. 표시 크기와 기기의 픽셀 밀도에 맞게 선택한다. 인트로의 이미지 선로딩도 같은 후보를 사용한다. 사용자가 제공한 char 원본과 실제 게임 판정용 sprite 파일은 보존했다.
5. 과거 비교 worktree 내부의 node_modules, dist, 생성 WASM 6개 경로만 정리했다. 실제 삭제 크기는 **622.79 MiB**다. 두 worktree의 소스, Git 등록, 원본 자산과 측정 자료는 유지했다. 정리 후 두 worktree의 git status --short는 비어 있었다.
6. 비교 worktree와 이번 검증 캡처 전용 폴더를 .gitignore에 추가했다. 재실행 가능한 clean-comparison-cache.ps1은 기본 dry run이며 -Apply일 때만 여섯 캐시 경로를 삭제한다. 모든 절대 경로와 부모 junction 여부를 먼저 검사한다.

## 빌드 용량 비교

초기 JS는 메인 파일 하나가 아니라 dist/index.html의 script 및 modulepreload로 필요한 모든 JS의 합계다. gzip은 동일한 Python gzip 계산 방식으로 비교했다. 외부 폰트·선택한 BGM·이미지·카메라 모델은 이 JS 합계에 포함하지 않는다.

| 항목 | 이전 | 적용 후 | 변화 |
| --- | ---: | ---: | ---: |
| 초기 JS 합계 | 571,804 bytes | 464,755 bytes | −18.72% |
| 초기 JS gzip 합계 | 183,187 bytes | 153,020 bytes | −16.47% |
| 캐릭터 UI 이미지 7종 합계 | 5,234,696 bytes | 1,630,044 bytes (640px) | −68.86% |
| 같은 이미지의 320px 후보 합계 | 위 원본 | 507,850 bytes | −90.30% |
| 같은 이미지의 960px 후보 합계 | 위 원본 | 3,257,290 bytes | −37.77% |

이미지 수치는 동일한 7개 자산 묶음의 비교이며 한 페이지의 실제 다운로드 총량은 아니다. 각 브라우저는 sizes와 DPR에 따라 후보 하나를 선택한다. 여러 해상도를 배포하므로 dist 전체 용량 감소와도 다르다. 다운로드 선택과 그림 비율은 브라우저 테스트로 확인했다.

공유 InputCoach와 cham 레이아웃 CSS는 RPS/Dodge/Gate에서도 쓰여 초기 로드에 유지했다. 실행 코드를 분리하면서 기존 스타일 순서와 공통 화면 구조를 보존하기 위한 조치다.

## 검사 중 확인하여 수정한 문제

- 길어진 안내 창의 스크롤 경계에 시작 버튼이 걸리면, 손 커서는 버튼 중앙 좌표에 있어도 클릭 대상을 찾지 못했다. 손으로 조작하는 시작/재개 버튼을 안내 창 내부 하단에 sticky로 유지해 가려지지 않도록 했다.
- 결과 레이아웃 테스트는 goto 직후 DOM이 이미 있다는 가정이 있었다. 동적 모듈의 렌더 완료를 기다린 다음 크기를 측정하도록 변경했다.
- 손 커서 테스트는 거의 같은 timestamp로 가짜 프레임을 연속 전달했다. 시간 기반 smoothing을 실제 카메라와 비슷한 50ms 간격으로 검증하도록 조정했다. 제품의 smoothing과 pinch 임계값은 바꾸지 않았다.
- 웹캠 자동 테스트는 병렬 실행 중 실제 대기 시간까지 가상 게임 시간에 반영되어 1개 벽의 점수가 달라지는 경우가 있었다. 모듈·카메라가 준비된 다음 가상 시계를 멈추고, 입력한 프레임만 게임 시간을 진행하도록 고정했다. 결과 화면에서는 시계를 다시 재개한다. 해당 완주/기록/달성 항목은 수정 후 재검증했다.

## 검증

- TypeScript/Vite 프로덕션 빌드 통과. 단일 청크 500 kB 경고 해소.
- 전체 게임의 입력·기록·일시정지·재시작·반응형 검사 및 실제 로컬 MediaPipe 모델 로딩 검사.
- 쏴!의 투명 영역 명중 제외, 무한/웨이브 모드와 결과 도전과제 목록 검사.
- 배포용 정적 파일의 경로별 직접 접속/새로고침, 초기 게임 청크 지연, 목적지별 prefetch, 의도적으로 지연한 청크의 이전 화면 유지, 모바일 이미지 선택 검사.
- 최종 배포용 검사 22개 통과. 손 메뉴 3종, 전체 결과 화면의 한국어/영어 반응형, 누끼 픽셀/해제, 벽 통과 웹캠 완주 검사를 수정 사항에 맞춰 재검증했다.
- 실제 사용자의 Windows 카메라 FPS/인식률, Galaxy S21 발열/지연은 이번에 재측정하지 않았다. 이번 결과는 용량과 동작 보존에 관한 것이며, 테스트 실행 시간으로 실기기 속도 향상을 주장하지 않는다.

## 유지한 작업

WASM 런타임 구성과 BGM 원본 갱신은 이번 최적화에 섞지 않았다. 호환성 검증이 필요한 런타임은 보존했다. BGM의 원본/배포본 차이는 audit-2026-11-17.md에 남긴 별도 점검 항목이다. FFmpeg 도구와 음원 원본도 유지했다.
