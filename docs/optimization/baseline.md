# 기준선 및 측정 한계

사용자가 정상이라고 확인한 `6845125`와 현행 `dbc0e36`의 프로덕션 빌드를 비교한다. 환경은 Windows 11 Pro 10.0.26200, Ryzen 5 3500X, RAM 약 16GB, Chrome 156.0.8078.74. 자동 탐색은 별도 headless Chrome, 가짜 카메라, 무인 영상, 1280×800, 각 1회, 3초 워밍업 후 10초이며 게임 대기 화면에서만 측정한다. 동일 Worker 메시지 송신→결과 수신 시간은 비트맵 생성·메시지 전달·큐 및 추론을 포함하는 소프트웨어 경계이며 순수 모델 시간이나 센서→화면 end-to-end가 아니다.

사용자의 실제 카메라: Sony Camera (Imaging Edge) 장치가 OS에 나타남. 실카메라 적용 설정은 아래 표와 같고, 실제 조명/거리, 동작별 정답과 기기 열 상태는 측정하지 않았다. 가짜 카메라는 실제 사용자의 입력을 재현하지 않으며 인식률 결론에 사용하지 않는다. 프로파일러·React 렌더 비용·계측 ON/OFF 오버헤드·cold/warm 5회·게임별 2분×3회·15분 연속 실행은 미완료. 정확도 비열등 기준 및 변동 범위는 실제 재현/기준선이 생긴 후 정해야 한다.

## Windows 실카메라 예비 비교

사용자가 각 게임을 시작한 뒤 F8로 측정을 시작했다. 각 버전/게임별 단 한 번, 약 10초의 연속 표본이며 6845125→현재 순서로 실행했다. 두 버전 모두 적용 설정 640×480, 30fps였다. 프레임 선택→Worker 결과 수신에는 비트맵 생성·전달·대기·추론이 포함된다. 센서→화면 지연이나 모델만의 시간, 정확도가 아니다. 조명·거리·열·동작의 동등성과 계측 오버헤드는 통제하지 않았고 측정 시작 시점의 실제 게임 상태나 동작 성공 횟수는 자동 확인하지 않았다. 같은 게임이라도 버전 간 규칙·입력 동작에 차이가 있다. 201 결과/200 송신처럼 시간 창 경계에서 이전에 보낸 결과가 들어올 수 있다. 원시 파일은 artifacts/optimization-live/에 있다.
