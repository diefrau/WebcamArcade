# 뚫어! 2차 — 기존 Pose 파이프라인 연결

## 구현

뚫어!의 기본 입력을 웹캠 상체 입력으로 전환했다. 카메라는 기존처럼 사용자의 연결 버튼으로만 켠다. 기존 `body.worker.ts`와 로컬 `pose_landmarker_lite.task`를 재사용하며 게임 컴포넌트가 MediaPipe를 호출하거나 Worker를 생성하지 않는다. `?input=mock`과 체험 입력 버튼은 기존 Mock 게임을 유지한다. 입력 전환은 시작 전만 가능하며 쿼리 변경 시 진행 상태를 초기화해 입력 출처가 섞이지 않게 한다.

## 공통 입력 경로

CameraProvider → bodySample(landmarks, actual frame time, image aspect) → visionSnapshot → GameInputAdapter → GatePoseTracker → 기존 advanceGate.

BodySample에는 프레임 시각·aspect 메타데이터만 추가했다. 기존 몸 중심·손·얼굴 판정 임계값은 유지한다. 새 어댑터의 Pose 좌표는 화면 기준으로 미러링하고 x에 이미지 종횡비를 적용해 실제 관절 방향을 비교한다. 목표 Mock 좌표는 정방형 수학 좌표이며, 스켈레톤·벽 구멍도 같은 비율로 표시한다. 위치·크기·상체 기울기의 영향을 줄이는 기존 정규화 및 관절 방향 비교를 사용한다.

## 준비 / 인식 유실

머리, 양 어깨, 팔꿈치, 손목이 프레임 내부에 있고 신뢰도가 충분할 때 준비를 시작한다. 어깨 중심·폭이 안정된 상태에서 최소 10개의 새 프레임과 1.2초를 확인한다. 모델 로딩 및 권한 대기 시간은 별도다. 웹캠 입력에서는 시작 버튼 대신 자동 시작 안내를 표시한다. 준비가 끝나면 마우스 없이 3초 카운트다운을 시작한다. 준비 상태를 다시 확인하는 버튼도 제공한다.

정규화 좌표에 70ms 시정수 EMA를 적용한다. 250ms 이상 입력이 끊기면 좌표를 이어서 보간하지 않는다. 900ms 이상 된 결과, 화면 밖·가려진 관절은 유효 입력으로 사용하지 않는다. 누락 시 유사도는 0이고 스켈레톤을 숨긴다. 짧은 유실은 게임을 계속 진행하지만 800ms 이상 이어지면 일시정지하며, 벽 교차 순간 유효 입력이 없으면 즉시 멈춰 유령 점수나 유실에 따른 강제 실패를 방지한다. 입력이 복구되기 전에는 재개할 수 없다.

## 화면 / 기록

웹캠 사각 프레임과 정규화한 스켈레톤을 제공한다. Segmentation 및 영상 누끼 합성은 아직 연결하지 않았다. 점수·결과·재시작은 Mock과 같은 게임 규칙을 사용한다. 웹캠 기록은 `arcade.gate.vision`, Mock 기록은 `arcade.gate.prototype`에 별도로 저장한다. 결과 새로고침과 다시 하기는 입력 출처를 유지한다. 뚫어!는 아직 체험판이며 온라인 랭킹·공식 도전과제에 제출하지 않는다.

## 기존 모드 현황

쏴! 웨이브·무한, 참참참 최고 난이도·술래, 빨리 피해! 60초·상하·무한(상하 조합 포함)은 기존 로컬 코드에 구현되어 있다. 사용자 SQL 실행 보고 이후 모드별 공개 랭킹 조회 성공을 확인했다. 실제 사용자 점수의 실서버 제출 시험과 웹 프런트엔드 배포는 별도로 확인해야 한다.

## 검증 및 한계

`tests/gate-pose.spec.ts`는 입력 시각, 종횡비·미러링, 준비 확인, 관절 유실·재개, 권한 거부 시 Mock 전환, 웹캠/Mock 저장 분리를 검증한다. 실제 로컬 Pose 모델이 뚫어!에서 한 번 로드되고 게임 이동 시 getUserMedia 요청이 추가되지 않는지도 검사한다. 현재 게임 선택 화면은 기존 손 인식 profile을 사용하므로 뚫어!→게임 선택→빨리 피해! 이동에서는 Pose→Hand→Pose Worker가 순차 전환되어 Pose 모델을 다시 요청한다. 모델 캐시는 이번 단계에 추가하지 않았다. 인식 동작의 자동 테스트는 합성 랜드마크·가짜 영상 장치 기반이며 사람의 실제 자세 인식률을 측정한 결과는 아니다. 실제 카메라의 거리·조명·목표 자세 난이도는 사람 참여 검증 후 조정해야 한다.

다음 단계는 같은 profile/worker 경계에서 opt-in Segmentation과 프레임 자원 반납을 연결하고, 느리거나 실패하는 환경에서는 현재의 사각 영상+스켈레톤을 유지하는 것이다.

## 이번 실행 결과

- 빌드(TypeScript/Vite) 통과. 기존 청크 크기 경고는 남아 있다.
- camera/dodge/endless-seeker/gate-pose/gate 선별 30개 항목에서 29개가 최초 통과했다. 한 항목은 게임 선택 화면의 Hand profile 전환을 빠뜨리고 Pose 재요청이 없어야 한다고 가정해 실패했다. 실제 수명주기와 카메라 재사용 조건을 명시한 뒤 그 항목을 재실행해 통과했다. 기존 몸·손·얼굴의 판정 임계값을 바꿔 통과시키지 않았다.
- 새 웹캠 흐름 테스트를 강화해 목표 자세 5개가 1,500점으로 저장됨을 확인했다. 모델 입력은 합성 랜드마크이며 실제 사람의 인식률을 뜻하지 않는다.
- 실제 로컬 MediaPipe Pose 모델 로딩 성공을 확인했다. /gate에서 한 번 로드되고, /games의 Hand profile을 거쳐 /dodge로 이동하면 Pose 모델은 순차 재로드되지만 카메라 권한·getUserMedia 스트림은 그대로 재사용된다.
- 웹 배포·Git 푸시는 수행하지 않았다. 로컬에서 /play/gate가 웹캠, /play/gate?input=mock이 Mock 입력이다.

모바일 390×844의 웹캠 준비 화면도 캡처해 가로 넘침이 없음을 확인했다. 카메라 연결 버튼이 추가된 준비 모달의 시작 버튼이 잘리지 않도록 모바일 웹캠 stage 높이를 조정하고, 버튼 경계가 모달 안에 들어오는지 다시 확인했다. `artifacts/gate-pose-ready-mobile.png`는 카메라를 켜지 않은 초기 화면이다.

## 2026-11-03 마우스 없는 시작·재개

웹캠 준비 확인이 끝나면 자동으로 3초 카운트다운을 시작한다. 추적 유실로 멈춘 경우 상체가 복구되어 1초 동안 유지되면 3초 카운트다운 후 저장된 벽 진행 상태에서 이어간다. 직접 일시정지한 경우에는 현재 자세만 유지해도 자동으로 풀리지 않는다. 양팔을 내린 뒤 다시 올려 1초 유지하면 같은 카운트다운으로 재개할 수 있다. 수동 재개 버튼도 유지한다. Mock 입력은 기존 시작 버튼을 유지한다.

자동 시작·재개는 문서가 보이고 포커스가 있으며 설정 dialog가 열리지 않은 상태에서만 허용한다. 자동 재개를 위한 대기와 카운트다운 중에는 벽 진행 및 점수를 변경하지 않는다. 합성 Pose 입력 테스트는 시작 버튼 클릭 없이 시작, 유실 후 자동 복구, 의도적 정지 유지, 팔 동작으로 재개 후 1,500점 완료를 검증한다.
