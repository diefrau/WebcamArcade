# WEBCAM ARCADE

시안 기반 React + TypeScript 웹캠 미니게임입니다. 홈 → 게임 선택 → 마우스 또는 손으로 ‘쏴!’ → 결과 → 다시 플레이 흐름을 제공합니다.

## 실행

```sh
npm install
npm run dev
```

터미널에 표시된 로컬 주소를 브라우저에서 엽니다.

```sh
npm run build
npm run preview
```

## 구현 범위

- `/`: 홈, 3개 게임 소개, 최고 기록, 오늘 플레이 횟수
- `/games`: 실제 카테고리 필터, 추천 게임, 준비 상태, 준비 중 게임을 포함한 6칸 구성
- `/play/shoot`: 30초 마우스/손 조준 게임, 5개 라이프, 콤보, 일시정지
- `/result/shoot`: 실제 점수·최대 콤보·정확도·최고 기록·결과에 따른 배지
- 한국어·영어 전환, 합성 효과음 켜기/끄기, 애니메이션 줄이기
- 브라우저 localStorage에 기록·설정 저장

카메라는 사용자가 ‘카메라 연결’ 또는 ‘손으로 플레이’를 누를 때만 권한을 요청합니다. 영상은 기기 내 Web Worker에서 처리하며 저장·업로드하지 않습니다. 화면 이동 중에는 연결을 유지하고, 카메라 끄기 버튼으로 모든 트랙을 종료합니다. 권한 거부·장치 없음·장치 사용 중·모델 로딩 실패 시 안내와 재시도를 제공합니다.

‘참!참!참!’, ‘원 그리기’, ‘쏴!’, ‘가위바위보’, ‘빨리 피해!’를 플레이할 수 있습니다. 랜덤 시작은 다섯 게임 중 하나를 엽니다. 미래 게임 1종과 이벤트는 준비 중입니다. 랭킹·도전과제는 기기 기록으로 사용할 수 있으며 Supabase 설정 후 온라인으로 확장됩니다. 기록과 미션 진행은 이 브라우저에 저장됩니다.

## 참!참!참! — Phase 10

`/play/cham` → `/result/cham`. 10라운드 동안 컴퓨터 화살표가 나타나면 0.9초 안에 **다른 방향**을 선택합니다. 피하면 100점, 같은 방향·무응답은 0점입니다. 버튼 또는 방향키로도 플레이할 수 있습니다.

얼굴 모드에서는 카메라 연결 후 정면을 보고 **정면 보정**을 누릅니다. 움직임이 적은 24프레임으로 기준을 잡습니다. 매 라운드 정면으로 돌아온 뒤 고개를 돌리세요. 화면의 거울 방향을 기준으로 좌우·상하를 판정하며, 한 방향을 100ms 유지하면 답을 확정합니다. 일시적인 얼굴 상실 동안 라운드는 계속 진행하며, 3초 이상 상실·카메라 오류·탭 숨김·설정 열기 시 일시정지하고 시간과 라운드를 보존합니다.

얼굴 모델은 참참참 화면에서만 로드하며 다른 게임으로 이동하면 기존 카메라 스트림을 재사용해 손 모델로 돌아옵니다. 눈 사이 선과 코 위치로 이동·크기·기울기를 보정한 상대 방향을 구합니다. 실제 장치에서 상하 민감도와 조명에 따른 인식 품질은 추가 확인이 필요합니다.

공식 [Face Landmarker 웹 가이드](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker/web_js)를 참고했으며 모델은 [Google float16 v1](https://storage.googleapis.com/mediapipe-models/face_landmarker/face_landmarker/float16/1/face_landmarker.task)을 `public/vision/face_landmarker.task`에 포함합니다. 영상은 기기 안의 Worker에서만 처리합니다.

원 그리기는 `/play/circle`에서 엄지·검지를 집은 동안만 검지 위치로 그리거나 마우스로 드래그합니다. 손가락을 펴면 커서만 이동하며, 다시 집을 때 선을 새로 시작합니다. 초록 커서는 이동, 분홍 커서는 그리기 상태입니다. 검지 좌표에 65ms 시간 기반 저역 통과 필터를 적용해 떨림을 줄이고, 인식 상실·일시정지 시 필터와 획을 초기화합니다. 완료 버튼으로 채점합니다. 얼굴/손 모델의 로컬 로딩, 입력 판정과 카메라 오류 복구는 자동 테스트로 확인하며, 사용자 실제 얼굴·손 영상은 테스트에 사용하지 않습니다.

## 손으로 플레이

‘쏴!’, ‘원 그리기’, ‘가위바위보’는 웹캠과 손 인식이 준비되면 준비·일시정지 화면에 손 커서가 나타납니다.
손을 움직여 시작/계속하기 버튼을 가리킨 뒤 엄지·검지를 집으면 버튼을 누릅니다.
버튼 위에서는 커서가 노란색으로 바뀌고 버튼에 초록 외곽선이 표시됩니다.
핀치는 한 번만 클릭하며, 시작·재개에 사용한 핀치는 발사나 그리기로 이어지지 않습니다.
손을 펴고 다시 집으면 게임 입력이 시작됩니다. 손을 잃거나 카메라를 끄면 메뉴 커서도 숨깁니다.

1. ‘쏴!’에서 ‘손으로 플레이’를 선택하고 카메라 권한을 허용합니다.
2. 모델 준비 후 손바닥을 카메라에 보여줍니다. ‘손 인식 완료’를 확인하고 시작합니다.
3. 손을 이동해 조준하고 엄지와 검지를 붙였다 떼면 한 발씩 발사됩니다.
4. 손이 0.8초 이상 보이지 않으면 게임이 일시정지합니다. 손을 다시 보여주거나 ‘마우스로 계속’을 선택합니다.

손목과 손가락 밑마디 5개 지점의 최근 5프레임 평균으로 조준합니다. 영상은 거울처럼 표시되며 조준 좌표도 좌우 반전합니다. 핀치는 손바닥 너비에 대한 엄지·검지 거리 비율로 판별하고, 열기/닫기 임계값을 분리해 떨림에 따른 연속 발사를 방지합니다. 영상 중앙 76%를 전체 조준 범위에 대응시켜 모서리에 접근하기 쉽게 했습니다. 모델 초기화와 추론은 Worker에서 실행하며 최대 약 24fps, 한 번에 한 프레임씩 처리합니다.

카메라는 localhost 또는 HTTPS에서 동작합니다. 실제 카메라·손을 이용한 조작감은 조명, 촬영 거리, 장치 성능에 따라 확인과 조정이 필요합니다.

## 게임 규칙

마우스로 과녁 캐릭터를 클릭하면 명중합니다. 연속 명중 시 100점부터 20점씩 추가하며, 한 발당 최대 300점입니다. 빗나가면 콤보가 초기화되고 라이프를 1개 잃습니다. 30초가 지나거나 5번 빗나가면 종료합니다. 일시정지 버튼 또는 Escape로 멈추고 재개할 수 있습니다. 탭이 숨겨지면 자동으로 일시정지합니다. 정확도는 명중 수 / 전체 발사 수입니다.

## 주요 파일

- `src/main.tsx`: 라우트, 공통 UI 컴포넌트, 게임 및 기록 관리
- `src/styles.css`: 디자인 토큰, 페이지 레이아웃, 반응형 및 접근성 스타일
- `src/comic.css`: 제공 시안에 맞춘 큰 제목·스티커·화면 비율·6칸 카드 배치
- `src/components/ComicArt.tsx`: 만화 장식 및 숲/목재 사격장 SVG
- `src/components/WebcamFrame.tsx`: 실제 영상, 손 랜드마크, 연결/오류 상태
- `src/vision/CameraProvider.tsx`: 카메라 생명주기, 로컬 Worker 통신 및 복구
- `src/vision/hand.worker.ts`, `src/vision/gestures.ts`: 추론, 조준 안정화, 핀치 발사
- `src/locales/ko.json`, `src/locales/en.json`: 번역 리소스
- `tests/arcade.spec.ts`: 실제 브라우저에서 흐름·기록·언어·일시정지 검증
- `tests/camera.spec.ts`: 가상 카메라 + 실제 모델 초기화, 권한/모델 오류, 연결 유지/종료, 합성 랜드마크로 조준·발사·손 상실 검증

공통 컴포넌트: Button, Sticker, Header, Logo, GameCard, Character, GameArt, WebcamFrame, Mascot, RecordsBar, SettingsDialog. 랜딩과 게임 카드에는 제공된 캐릭터 에셋을 사용하고, 플레이 목표물과 사격장 등은 SVG입니다. 글꼴은 Google Fonts에서 불러오므로 최초 로딩에는 네트워크가 필요합니다.

## Phase 11 — Bouncy 연출

- 버튼·게임 카드에 탄성 있는 hover/press 반응, 준비 팝업·결과 점수·스티커에 순차 등장 연출을 적용했습니다. 명중/실패와 참참참 카운트다운·방향 판정은 이벤트마다 다시 튀어 오릅니다.
- 페이지는 로딩 스크린이나 강제 대기 없이 바로 표시됩니다. 이미지와 웹폰트는 브라우저가 일반 방식으로 로드합니다. 카메라 권한과 인식 모델 준비 상태는 카메라 패널에서 안내합니다.
- OS의 reduced-motion과 앱의 ‘애니메이션 줄이기’ 모두 지원합니다.

## Phase 11 — 효과음·보상·입력 안정성 마무리

- 공용 Web Audio 엔진으로 시작·성공·실패·콤보·일시정지·재개·결과·최고 기록 효과음을 구분합니다. 사용자 입력으로 오디오가 활성화되며 음소거 시 재생 중인 소리와 예약된 음을 즉시 취소합니다. 원 그리기에도 동일한 효과음을 적용했습니다.
- 세 게임 결과에 화면 진입 즉시 시작하는 850ms 점수 카운트업과 최고 기록 스티커를 적용했습니다. 양수 점수에는 짧은 색종이 연출, 0점에는 격려를 표시합니다. OS 또는 앱의 애니메이션 줄이기가 켜지면 점수를 즉시 표시하고 색종이를 생략합니다. 결과 연출은 저장된 점수·기록을 변경하지 않습니다.
- 퇴화한 손 좌표의 가짜 핀치, 비정상 좌표·화면 비율을 차단합니다. 마지막 손·얼굴 표본을 900ms 뒤 무효화하고 늦게 도착한 결과를 거부합니다. 기존 손 게임의 800ms 유예와 모델의 6초 오류·재시도 흐름은 유지합니다. 실제 사용자 손·얼굴 민감도는 장치 테스트가 필요합니다.
- 프로덕션 빌드 후 `/games`, 세 `/play/*`, 세 `/result/*` 경로의 진입 HTML과 `404.html`을 생성하여 GitHub Pages 직접 접속·새로고침을 지원합니다. 디렉터리 끝의 `/`만 React 실행 전에 정리하며 쿼리와 해시는 유지합니다.
- `npm run test:pages`는 빌드한 파일을 SPA fallback 없는 정적 서버에서 검증합니다.

## Phase 12 — 가위바위보

`/play/rps` → `/result/rps`. 5라운드, 각 라운드 1.5초 카운트다운 뒤 3초 안에
바위·보·가위를 선택합니다. 승리 100점, 무승부 30점이며 무응답은 0점입니다.
컴퓨터의 선택은 입력 전에 정하고, 답을 확정한 뒤 공개합니다.

- 웹캠 모드: 손바닥을 카메라 쪽으로 두고 손 모양을 약 250ms 유지하면 답을 확정합니다.
  네 손가락의 관절 각도와 손목에서의 상대 거리를 사용하며, 애매한 모양은 판정하지 않습니다.
  정면 손바닥의 보, 주먹의 바위, 검지·중지를 편 가위를 인식합니다.
- 버튼 모드: 바위/보/가위 버튼 또는 숫자키 1/2/3을 사용합니다. Escape로 일시정지합니다.
- 손 인식 상실 시 800ms 뒤 멈추고, 카메라가 돌아오거나 버튼 모드로 전환하면 남은 시간부터 재개합니다.
  설정 열기와 탭 숨김도 일시정지합니다.
- 최고 기록·플레이 횟수·라운드 결과는 `arcade.rps`에 저장하고, 하루 플레이 횟수에도 반영합니다.
  저장 실패 시 결과를 화면에 유지하고 안내합니다.
- 게임 선택의 가위바위보 카드, 랜덤 시작, 기록 바, 한국어·영어, 손 커서로 시작/재개를 연결했습니다.
  홈의 추천 카드는 기존 3개 구성을 유지합니다.
- `tests/rps.spec.ts`는 9가지 승패 조합, 손 모양의 회전/크기/좌우 반전, 버튼·키보드 진행,
  시간 초과·저장·재시작·웹캠 입력·손 상실·반응형을 검증합니다. 실제 손의 촬영 각도와 조명에 따른
  인식 품질은 장치에서 조정할 수 있습니다.

## Phase 13 — 빨리 피해!

`/play/dodge` → `/result/dodge`. 상체를 좌우로 움직여 떨어지는 별을 피하는 30초 생존 게임입니다.

- Google Pose Landmarker Lite의 양쪽 어깨를 사용합니다. 시작 시 현재 위치와 어깨 폭을 보정하고, 거울 방향으로 이동합니다. 두 어깨의 visibility가 0.6 이상일 때만 입력을 받습니다. 90ms 시간 기반 필터로 이동을 부드럽게 처리합니다.
- 방향키 또는 A/D, 누르고 있는 화면 버튼으로도 이동합니다. 카메라를 연결하면 몸 모드를 선택하며, 몸 모드에서 끊기면 자동 정지합니다. 인식 상실은 800ms 유예 뒤 정지하고, 설정·탭 숨김·포커스 상실도 정지합니다. 보정 버튼은 준비·일시정지에서 사용할 수 있습니다.
- 3초 카운트다운, 라이프 3개, 충돌 뒤 1초 무적. 시간이 지날수록 낙하 속도와 등장 빈도가 올라갑니다. 생존 1초당 10점, 통과한 별당 50점입니다. 30초 생존 또는 라이프 소진 시 결과를 저장합니다.
- 최고 기록·플레이 횟수·마지막 결과는 `arcade.dodge`에 저장하며 하루 플레이 횟수, 게임 카드, 랜덤 시작, 기록 바와 연결됩니다. 한국어·영어와 모바일 화면을 지원합니다. 홈 추천 3개 구성은 유지합니다.
- 모델은 [Google 공식 웹 가이드](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js)를 따르며 [Pose Landmarker Lite float16 v1](https://storage.googleapis.com/mediapipe-models/pose_landmarker/pose_landmarker_lite/float16/1/pose_landmarker_lite.task)을 `public/vision/pose_landmarker_lite.task`에 포함했습니다. 전용 Worker에서 처리하고 촬영 영상은 저장·업로드하지 않습니다.
- `tests/dodge.spec.ts`에서 충돌·무적·승패 종료·점수·기록·카메라 보정·인식 상실·대체 입력·실제 로컬 모델 로딩을 확인합니다. 자동 테스트의 카메라는 가상 장치이며 실제 사람의 조명·촬영 거리별 인식 품질은 장치 확인이 필요합니다.

## 랭킹·도전과제 / 얼굴 입력 / 터치 환경

- `/ranking`, `/achievements`: 기기 최고 기록과 완료 이력에 따른 도전과제 8개. Supabase 연결 후 익명 또는 선택 닉네임으로 게임별 온라인 랭킹과 SQL 도전과제를 제공합니다. 실제 프로젝트 연결 절차는 [Supabase 설정 문서](supabase/README.md)에 있습니다. 도전과제는 이 업데이트 이후 완료한 게임부터 집계합니다.
- 얼굴 게임은 더 작은 움직임을 100ms 유지하면 판정하고, 잠깐의 추적 상실에도 라운드를 진행합니다. 추적이 없을 때 임의의 방향을 만들지 않습니다. 3초 연속 상실이나 카메라 오류에는 일시정지합니다. 모델이 완전한 옆얼굴까지 항상 인식하는 것은 아니므로 실제 장치에서 확인이 필요합니다.
- JavaScript에서 `maxTouchPoints`, 주 포인터의 `pointer: coarse`, 현재 폭을 함께 확인합니다. 터치 환경에는 터치 안내와 44px 이상의 버튼을 제공하고 손 메뉴 커서·마우스 조준선·일부 장식을 숨깁니다. 화면 폭만으로 터치 장치라고 간주하지 않으며, 키보드·마우스를 주로 쓰는 넓은 터치 노트북은 데스크톱 조작을 유지합니다. 웹캠 모드는 선택할 수 있습니다.

## MediaPipe 자산

구현은 [Google Hand Landmarker 웹 가이드](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/web_js)를 따릅니다. `@mediapipe/tasks-vision`은 Apache-2.0 라이선스이며, npm 설치/빌드 시 `scripts/prepare-vision.mjs`가 해당 버전의 WASM 런타임을 `public/vision/wasm/`에 복사합니다. 이 폴더는 자동 생성되므로 Git에서 제외했습니다.

`public/vision/hand_landmarker.task`는 [Google의 Hand Landmarker float16 모델 v1](https://storage.googleapis.com/mediapipe-models/hand_landmarker/hand_landmarker/float16/1/hand_landmarker.task)입니다. 모델과 WASM은 사이트에 포함되므로 플레이 중 외부 CDN에서 받지 않습니다. 빌드 시 `public/vision/` 파일도 함께 배포해야 합니다. 자동 테스트에는 사용자의 실제 카메라를 사용하지 않습니다.
